# Scroll and output planning

Use when the requested design spans a continuous page or multiple dependent outputs. Plan content order, first-viewport priority, continuity, and reachable actions for the chosen artifact. A specification can describe each section's job. A runnable page uses natural scroll, with representative viewport or full-page browser evidence when needed.

## When generated scroll bands are authorized

For a coherent full-scroll page or site, freeze coverage topology and set choreography before the first artifact. Use `artifactTopology: separate-bands` for landing/storefront/multi-section pages; reserve `single-tall` for an explicit user request to generate the entire overview in one call. Derive `continuityRequirement: system-coherent | authored-breaks | seamless-page`, canvas role/target aspect, and output count from legibility, hierarchy, scroll semantics, protected reachability, downstream evidence, and continuity risk; do not default to one screenshot, two screens, or a fixed call count. Generate the top and continuation bands serially at the full target desktop width and normal viewport height. Let each band's content use that canvas at a readable UI scale; do not fit the entire page into one long image before those source bands exist. Derive the number of bands from section jobs, not a fixed count. When the requested deliverable includes one continuous complete-page image, freeze its assembly method first: ImageGen by default, local-only if explicitly requested. A requested set of separate design/state images needs no extra assembly output unless a continuous composite is also required. Only the ImageGen method adds a final assembly output with ordered source IDs, their union content, target canvas, preservation/join rules, and one additional call per page. This derived output does not add a route, product state, or content band; it reuses reviewed content. In FULL, declare that ImageGen output's source dependencies and design-evidence obligation before confirmation. An explicit local-only delivery does not add an ImageGen assembly checkpoint or call; review its local composite under the requested method. A request for one homepage, final PNG, or preview is not authorization for the one-call overview exception. If the user explicitly chooses that method, record the exception before rendering; it is not a viewport or device screenshot. When seamless-page continuity is material, require target-scale full-page evidence; if ImageGen cannot satisfy it within the frozen attempt budget, reconsider artifact choice through `artifact-choice-and-validation.md` instead of adding unplanned seam-repair calls or silently relaxing the requirement.

Keep global visual-system invariants separate from each output's perceptual job. For every ordered output declare shell role/ownership/chrome, representation signature, visual signature (`layoutGrammar`, `focalBehavior`, `density`, `imageTextRatio`, `assetFamily`, and `hierarchy`), imagery slots and reuse policy, transition mode, and visual-anchor scope. A continuous-page root owns shell chrome once; continuations inherit it and are headerless unless persistent chrome is explicitly required for viewport evidence or product behavior. Generated scenes and crops are unique by default; repetition requires an explicitly shared semantic asset, not merely the desire for consistency. Use signature distance as an anti-template diagnostic rather than a difference quota: continuity may preserve many fields, but a copy-swapped shell is not a distinct band.

For each separate-band boundary, choose the least contaminating reference exposure that can preserve the invariant: no pixels when textual direction is sufficient; a scoped region or deterministic system capsule for exact type/material/boundary evidence when current imagery/layout must stay unique; the full accepted immediate predecessor only when an exact continued spatial, structural, shell, or asset relationship itself must survive. Shared typography, palette, material, or mood roles alone do not justify full-screen exposure. State what may and must not influence the result, and never reuse one distant root artifact as the generic anchor for all later bands. Product Design freezes this choice together with exit/entry states, a handoff carrier, and an edge treatment; the renderer does not infer continuity from ordering alone.
